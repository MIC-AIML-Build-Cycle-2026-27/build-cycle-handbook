# Review 1: Foundation + Proof of Concept

**Dates:** Saturday 31 October → Tuesday 3 November 2026
**Milestone due:** 3 November 2026
**Phases covered:** Foundation, Proof of Concept

## Goal

Show that the team understands the problem, has a sensible plan and setup, and that **the core idea works in at least a minimal form**.

## Expected

- **Architecture / setup**
  - Scope agreed and written in the README (Overview, Problem Statement, Objective, Proposed Solution)
  - First version of `docs/architecture.md`: main components and how they connect
  - Repository set up: structure adapted to the project, dependencies installable, README *Getting Started* works
- **Core modules started**
  - Issues created for the main work, assigned, and attached to milestones
  - Code for the core modules started and merged through PRs
- **Working proof of concept**
  - A minimal demo of the main idea working on real or realistic input
  - It can be rough and narrow, but it must actually run

## Evidence to bring

| Item | Where |
|---|---|
| Updated README | Repository |
| Architecture draft | `docs/architecture.md` |
| Project board with issues and assignees | Team project board |
| POC demo (live or recorded) | Review session |
| Review update | [`templates/review-update.md`](../templates/review-update.md), saved as `docs/updates/review-1.md` |

## Questions reviewers are likely to ask

- What exactly is the problem, and who is it for?
- What does the POC prove, and what does it not prove yet?
- What are the biggest technical risks, and what is the plan for them?
- How is the work divided? Does everyone have something they own?
- What is planned for Review 2?

## Team-specific requirements

Project Leads may add requirements for their team. List them in the README under *Build Cycle Milestones → Review 1*.

## After the review

- Record the feedback as issues (or in `docs/updates/review-1.md`).
- Move unfinished Review 1 issues to *Review 2* deliberately.
- Optional: tag `v0.1.0` (see [Releases](github-guide.md#releases)).
